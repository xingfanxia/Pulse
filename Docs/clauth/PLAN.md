# CLP — Pulse × clauth: the rail absorbs ccsbar

Status: **CLP-0 planned 2026-09-02, reviewed (42 findings, 25 upheld, all folded in)** · executes as one `/goal` (`GOAL-PROMPTS.md`) · CLP-1 → CLP-3 in this run, CLP-4 human-gated.

## Objective

Pulse's floating rail becomes the one always-on surface for every account clauth manages — **every claude profile and every codex profile, one ring each** — and gains clauth's full control face (switch, chain, thresholds, proxy mode, rolling token, add/rename/delete) so ccsbar can retire. Pulse holds **zero tokens** for these accounts: clauth's daemon is the data plane (`~/.clauth/status.json` + `~/.clauth/clauthd.sock`), Pulse renders and sends commands.

Why this shape (decided 2026-09-02, AX): the menu-bar label ccsbar owns has a 12-character budget — N accounts × 2 harnesses cannot fit. A ring per account on a rail is the correct display, and Pulse already built it (floating `NSPanel`, edge docking, sliver fold, multi-display memory, ~2.5k LOC of edge cases). Porting that into ccsbar means maintaining a fork of it by hand; consuming it as a fork means upstream fixes arrive by merge.

## The one architectural rule — all logic in new files, hooks are one-liners

Upstream `qunqin24/Pulse` was born 2026-08-30 and landed 100 commits in four days; `SettingsView.swift` (1434 LOC) changed 35 times in that window, `UsageStore.swift` 19, `AppSettings.swift` 18, `UsageDockView.swift` 14, `UsageDetailCard.swift` 13 (`git log --since='60 days ago'`, 2026-09-02). Anything written *inside* those files is a merge conflict every week. Therefore:

- Every clauth file lives under `Sources/Pulse/Clauth/` (SwiftPM includes subdirectories of the target path — verified with a scratch package 2026-09-02). Upstream never touches that folder.
- Upstream-owned files receive **call-site hooks only**: an appended array, a `case`, a modifier, a guard, a stored property with a `didSet` that calls into `Clauth/` — each ≤3 lines. The total is enforced by `Scripts/clauth-hook-budget.sh` (added lines in upstream-owned Swift files; `.strings`, `Package.swift`, `Docs/`, `.agent/` exempt). **Budgets: CLP-1 28 · CLP-2 36 · CLP-3 52.**
- **The graders are frozen.** `Scripts/clauth-verify.sh` and `Scripts/clauth-hook-budget.sh` were written and committed by the authoring session BEFORE the goal fires; the executor never edits them (`git diff <kickoff-sha> -- Scripts/clauth-*.sh` must be empty at every milestone — it is one of the acceptance lines).
- `main` tracks `upstream/main` by **true merge**, weekly or before each milestone; never rebased, never force-pushed. Our commits carry a `clp(N):` prefix so `git log --grep` separates the two lines.
- No release tags on the fork (a tag drives upstream's Sparkle release workflow); the app is installed from a local `Scripts/bundle.sh` build.

## Milestones

### CLP-1 — clauth accounts on the rail (read-only)

Deliverable: launch the bare build with `PULSE_CLAUTH_HOME=<sandbox>` → one ring per fixture profile, both harnesses, numbers identical to the fixture, no network request for them, and the same rings after quit + relaunch.

- `Clauth/ClauthStatus.swift` — `Codable` mirror of status.json (decodeIfPresent everywhere; `rolling_token` ?? `session_feed`; schema ≠ 1 → unsupported). Port from ccsbar `DaemonStatus.swift` minus its view helpers.
- `Clauth/ClauthWatcher.swift` — mtime-polled (2s) reader of `${PULSE_CLAUTH_HOME:-~/.clauth}/status.json`; publishes the roster into `AppSettings.clauthAccounts` and readings into `UsageStore.applyClauth`. Owned and started from `AppDelegate` (one stored property + one `start()` next to `store.start()` — 2 hook lines).
- `Clauth/ClauthMapping.swift` — pure: profile → `AccountKey(.claudeCode|.codex, slot: "clauth:<name>")` (third-party providers → `.claudeCode` with `plan` = provider); windows → `UsageWindow`: `5h`→`.fiveHour`/18000s, `7d`→`.weekly`/604800s, `7d <model>`→`.weekly` scope=`<model>`; **any other label is DROPPED** (Pulse's own rule: never invent a length); `isExhausted` = ccsbar's three-part rule verbatim (99.5 · reset still ahead, missing = spent · scoped never) ∨ codex verdict leg (named window → that window's `resets_at`; bare reason → either window's; lapsed → no); `state` = `.stale` when `stale == true` OR the liveness ladder reads `.dead`, else `.live` (a `Cached` reading is still a reading); `observedAt` = `fetched_at`; `plan` = tier; codex `creditBalance` = "1 reset banked" when `codex_reset_credits > 0`.
- `Clauth/ClauthVisibility.swift` — owns the visibility state Pulse's `enabledAccounts` cannot hold: `clauthHiddenAccounts: Set<String>` (our UserDefaults key, default empty = every clauth profile shown) and `clauthHidesPrimaries: Bool` (default true once a feed is seen; user-toggleable in the clauth pane). ## Safety rails (死规矩)

- Pulse reads `status.json`, `tokens.json`, `${PULSE_CODEX_HOME:-~/.codex}/config.toml`, and the socket. It NEVER reads `~/.clauth/profiles/*/credentials.json`, `codex-auth.json`, `session-token*`, `~/.claude/.credentials.json`, the Keychain, or `~/.codex/auth.json`. A clauth account is never a Pulse `ExtraAccount` with copied tokens. (Gate 5 of the verify script.)
- Every process spawn goes through `ClauthCLI.swift` (gate 6), which refuses to spawn under `PULSE_CLAUTH_HOME` unless `PULSE_CLAUTH_BIN` points at the sandbox's recording shim. During development the executor never sends `switch`, `rename`, `delete`, `fallback_*`, `set_*`, `login`, `rolling-token`, or `launchctl` to the REAL daemon/system: all interactive verification runs with `PULSE_CLAUTH_HOME=<sandbox> PULSE_CLAUTH_BIN=<sandbox>/bin/clauth PULSE_CODEX_HOME=<sandbox>/codex` against the fixture, the fake socket, and the shim. Read-only smoke against the real daemon is allowed: reading `~/.clauth/status.json`, `{"cmd":"snapshot"}`. `~/.clauth/daemon.log` must show no switch/rename/delete line stamped inside the run window.
- Live switches and browser OAuth on AX's real accounts are AX-manual (project rule) — the closeout lists them as the first thing AX does after install.
- No edits to `.github/workflows/*`, `appcast.xml`, `Scripts/appcast.py`, `Scripts/dmg.sh`, `Scripts/bundle.sh`, `VERSION`, `CHANGELOG.md` (gate 7); no tags; no edits to `Scripts/clauth-*.sh`.
- Sandbox runs use the BARE build (`swift build` product), never `/Applications/Pulse.app`: Sparkle is inert there and UserDefaults land in the `Pulse` domain, not the installed app's.
